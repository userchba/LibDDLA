# LibDDLA 0.0.7 migration and release guide

Status: **in preparation**, not yet tagged or published by this work.
The comparison baseline is `v0.0.6` (`7f2675d`). The preparation audit used
`develop` at `b4189ff` on 2026-11-21. Later source changes need their own review.
See the [changelog](../../CHANGELOG.md) for the user-facing summary and the
[README](../../README.md) for detailed build and API contracts.

## Upgrade requirements

This is a source-incompatible pre-1.0 release. Rebuild LibDDLA and its
applications together in a clean build directory. Do not mix 0.0.6 headers,
0.0.7 libraries or old language-binding binaries. The shared-library SONAME
still tracks major version 0; this does **not** establish ABI compatibility.
The version source is `src/version.h`; CMake derives the package and library
versions from it.

| Requirement | 0.0.7 contract |
| --- | --- |
| Compiler | C++17 to build; C++11 or newer for public-header consumers |
| CPU dependencies | MPI and BLAS/LAPACK, including CBLAS complex dot interfaces, in every build |
| GPU selection | Optional CUDA or HIP, mutually exclusive; CPU remains available |
| Public headers | `<ddla/ddla.h>` and the other installed `ddla/` headers |
| CMake consumer | `find_package(LibDDLA REQUIRED CONFIG)`, target `ddla::ddla` |
| Dimensions | LP64 `int` dimensions/indices and ScaLAPACK-compatible `int[9]` descriptors |

### Backend and communication selection

Remove backend template arguments from public computational calls. Initialize
each handle explicitly; there is no implicit default backend:

```cpp
// After MPI_Init_thread; all ranks use a compatible collective order.
ddla::DdlaHandle_t handle = nullptr;
ddla::DDLA_CHECK(ddla::ddlaInit(handle, ddla::DdlaBackend::CPU));
ddla::DDLA_CHECK(ddla::ddlaSet(handle, MPI_COMM_WORLD, 'R'));
// Former gemm<Backend, double>(...):
ddla::gemm<double>(handle, 'N', 'N', m, n, k,
                   alpha, A, lda, B, ldb, beta, C, ldc);
// Destroy owned ddla::vector buffers before destroying this handle.
ddla::DDLA_CHECK(ddla::ddlaDestroy(handle));
```

This is a call-shape example: initialize dimensions, scalars and buffers before
use. Select `DdlaBackend::GPU` for device data in a GPU-enabled build. Memory,
copy and event operations also take the handle. `ddla::vector<T>` selects its
memory domain through that handle and does not initialize its elements.

Replace public capability checks based on `DDLA_HAS_CPU` or vendor-specific
stand-ins with `DDLA_HAS_GPU` where a GPU capability check is needed. CPU is
unconditional. Do not export private `DDLA_USE_*` definitions to applications.
`DDLA_USE_CUDA`, `DDLA_USE_HIP` and `DDLA_USE_CCL` remain library build options.

CPU handles use MPI. GPU handles can select MPI, `HostStagedMPI`, or CCL when
compiled in, through `ddlaSetCommunication`. GPU MPI requires a GPU-aware MPI
stack; an availability query cannot prove that the installed MPI accepts device
pointers. Choose host staging for an MPI stack without device-buffer support.
After grid setup, changing transport is collective and requires idle handles;
re-prepare transport-dependent private workspaces after a change.

Fortran initialization is `ddla_init_backend(handle, backend)`. Python requires
`Handle(backend=Backend.CPU)` or `Handle(backend=Backend.GPU)`. Check each binding's
exported coverage rather than assuming every new C++ entry has a wrapper.

### Factorizations and redistribution

- **LU:** `pgetrf`, `pgetrs` and public `plapiv` take pivots in the selected
  backend. Use `ddla::vector<int>` sized for local rows of the full factor
  descriptor. Indices remain one-based global row indices, distributed by
  process row and replicated across process columns. GPU code inspecting
  pivots on the host must copy and synchronize explicitly.
- **Cholesky:** remove `is_head`/`location` arguments and boolean return-value
  handling from `ppotrf`; check host `info` instead. `info>0` reports a
  non-positive pivot. The obsolete head correction is not part of the solver.
- **QR/QL:** replace distributed `pgeqrf(handle, 'U', ...)` with
  `pgeqrf(handle, ...)`, and `'L'` with `pgeqlf(handle, ...)`. This split applies
  to the distributed interface; local `geqrf` retains its `uplo` argument.
  Distributed QR/QL `tau` uses host local-column indices. New LQ/RQ entries
  use host local-row indices; local factorization `tau` uses backend memory.
- **Redistribution:** replace removed `transport_block` uses with the appropriate
  `pgeadd` panel redistribution, respecting its one-based origins and N/T/C
  operation. It is not a mechanical argument-for-argument rename.

### Dense and tridiagonal eigensolvers

The public PHEEVD/PSTEDC entries were added after the v0.0.6 tag. This section
also covers migration from their intermediate `develop` signatures; it does
not imply that those entries were public APIs in the tagged 0.0.6 release.

`pheevd`, `pheevd_one_stage` and `pheevd_two_stage` require `nev` immediately
after `n`:

```cpp
ddla::pheevd<double>(handle, 'V', 'U', n, nev,
                     A, descA, w, Z, descZ, info);
```

Use `nev=n` to preserve full-vector output. `w` is a replicated host array of
length **n**, even when `nev` is small. `Z` covers `n × nev` with the method's
descriptor requirements. `nev=0` skips vectors, and `jobz='N'` returns only
values for any valid `nev`. A is destroyed; these calls do not preserve its
unused triangle as a separate output. Matrix-sized storage remains distributed;
small replicated vectors/metadata and bounded panels are permitted.

The default tridiagonal method is divide and conquer (`dc`). For `0<nev<n`,
`DDLA_EIG_TRIDIAGONAL=selected` explicitly enables selected vectors inside the
one-/two-stage drivers. All ranks must use the same option. It obtains all n
public eigenvalues with native STERF, uses STEBZ for private selected shifts,
and LAGTF/LAGTS for bounded inverse iteration with reorthogonalization and
certification. It does **not** first run PSTEDC for a full set of vectors.
Inverse iteration runs on CPUs even for GPU handles; bounded row panels are
uploaded for GPU back-transforms. Tridiagonal-stage storage is approximately
`O(n*nev/P + n + P)` per rank, with uneven ownership and panel overhead.
This is not a whole-solver peak-memory bound. Failure is reported rather than
silently allocating a full-vector divide-and-conquer fallback.

Standalone PSTEDC now uses:

```cpp
ddla::pstedc<double>(handle, 'V', n, nblk, d, e, w, z, ldz, info);
```

Only `'N'` (values) and `'V'` (values/vectors) modes are supported. `nblk` must
be positive. `d`, `e` and `w` are replicated host arrays; input `d/e` are
destroyed. `z` is in backend memory with all n columns and contiguous row slabs
over communicator ranks. Rank q of P owns `n/P + (q < n%P)` rows, beginning at
`q*(n/P) + min(q,n%P)`, with `ldz >= max(1,local_rows)`. The old `descZ` output
is removed; redistribute to a 2D descriptor if needed. For `'N'`, z may be null.
`DDLA_EIG_DC_LEAF` no longer controls distributed leaves. `nblk` balances local
problem ownership; it does not set the GPU engine's bounded numerical leaf size.

For `nev << n`, consider the separate `pheevd_chebyshev` API. It returns only
**nev** host eigenvalues, unlike `pheevd`; controls for extra vectors, tolerance,
iteration limit, degree and warm start are required. It destroys A by scaling
and completion. It is never selected automatically, and residual convergence
alone does not certify that no lower eigenvalue was missed. See the
[partial iterative solver contract](../../README.md#partial-iterative-hermitian-eigenproblems).

### SVD and generalized problems

`pgesvd` uses distributed bidiagonal divide and conquer for vector output;
`pbdsdc` returns row-distributed factors. Replicated/root-gather spectral routes
are removed. The obsolete `DDLA_SVD_BDSOLVER` selector is ignored. Direct
bidiagonalization remains the default; `DDLA_SVD_SHAPE=qr` opts into eligible
tall/wide reductions and can change workspace and runtime.

`phegvd` solves distributed `A X = B X Lambda` with positive-definite B and
returns all n eigenvalues plus the lowest nev vectors. It destroys A and stores
B's Cholesky factor in B. For repeated problems, factor B once and use `phegst`
with the reusable factor; this reduction does not refactor B.

## Performance and limitations

No release-wide 2x speedup is promised. Mixed products, triangular output,
communication overlap and solver routing depend on dimensions, scalar types,
layout, transport and hardware. Compare equivalent operations and record
correctness, peak per-rank memory and transfer-inclusive timing.

A dated double-precision PSTEDC comparison (all vectors, nblk=128, tridiagonal
fixture kind 6, ABBA medians) measured the rank-local STEDC change as follows.
The retained HPC3 comparisons include CPU job 4049075 and four-GPU job
4049361. These are that change's frozen baseline/candidate results, **not** measurements
of the final 0.0.7 release against 0.0.6:

| Configuration | n | Before (ms) | After (ms) | Result |
| --- | ---: | ---: | ---: | --- |
| CPU, 4 ranks × 12 cores | 5000 | 182.558 | 185.658 | 1.7% slower |
| CPU, 4 ranks × 12 cores | 10000 | 897.765 | 946.943 | 5.5% slower |
| Two V100 GPUs | 5000 | 145.7785 | 123.567 | 1.18x speedup |
| Two V100 GPUs | 10000 | 517.8065 | 500.29 | 1.035x speedup |
| Four V100 GPUs | 5000 | 104.962 | 78.8275 | 1.33x speedup |
| Four V100 GPUs | 10000 | 363.2545 | 310.9265 | 1.17x speedup |

The CPU regression was explicitly accepted. GPU automatic eigensolver thresholds
are scoped to measured profiles, not portable speed guarantees. Homogeneous
variable-size batched GEMM is GPU-only; mixed-domain variable-size overloads
also support CPU host metadata. Distributed memory bounds include descriptor
rounding/empty partitions; vendor first-use allocations are not eliminated by
LibDDLA's reusable workspace or host-staging reservation.

3m18s. It used GCC 11.3.0, OpenMPI 4.1.8-cuda, CUDA 11.8, OpenBLAS 0.3.29
and two allocated V100 GPUs. A fresh CPU+CUDA/CCL library was built from

The tested source archive SHA-256 is
`73fc745223bf51cf53ed65207e0fe4739fbac363bc5874fdd47845e01ff34ae7`.
